EN005 – Intermittent Test Output in Godot Editor

Fecha:
2026-08-15

Tema:

Salida vacía o parcial al ejecutar escenas
de prueba desde el editor de Godot.

Entorno:

Godot Engine:
4.7.1.stable.official.a13da4feb

Renderer:
D3D12 Forward+

Síntoma:

Al ejecutar escenas de prueba mediante
Run Current Scene, algunas ejecuciones:

- no mostraban salida;
- mostraban salida parcial;
- mostraban la salida completa después
  de repetir la ejecución.

El comportamiento era aleatorio.

El proceso de depuración sí comenzaba.

Hipótesis inicial:

SceneTree terminaba antes de que el panel Output
procesara todos los print().

Experimento 1:

Sustituir quit() inmediato por:

call_deferred("quit")

Resultado:

La salida continuó siendo aleatoria.

Conclusión:

call_deferred() no resolvió el problema.

Experimento 2:

Esperar dos process_frame antes de quit().

Resultado:

La salida continuó siendo aleatoria mientras
la limpieza automática del panel permanecía activa.

Conclusión:

La terminación rápida no era la única causa.

Hallazgo:

Godot Editor tenía activa la configuración:

Run
→ Output
→ Always Clear Output on Play

El editor limpiaba automáticamente el panel
al comenzar una ejecución.

Las escenas de prueba producen salida muy pronto.

Se observó una condición de timing entre:

- inicio del proceso;
- impresión inicial;
- limpieza automática del panel.

Experimento 3:

Desactivar:

Always Clear Output on Play

y limpiar el panel manualmente antes de cada prueba.

Resultado:

10 ejecuciones consecutivas completas.

10 COMPLETE.

0 PARTIAL.

0 EMPTY.

Conclusión:

La limpieza automática del panel era la causa
de la salida intermitente observada.

Decisión:

Durante el desarrollo y ejecución manual de pruebas:

Always Clear Output on Play:
OFF

Antes de cada prueba:

El desarrollador limpiará manualmente
el panel Output.

No se modificarán los baselines existentes.

No se añadirán:

- delays;
- timers;
- frames de espera;
- call_deferred();
- lógica de sincronización artificial;

únicamente para mostrar resultados en el editor.

La configuración pertenece al entorno de desarrollo,
no al código del proyecto.

Estado:

VERIFICADO

Seguimiento posterior:

Después de desactivar:

Always Clear Output on Play

se observó nuevamente el comportamiento:

STARTED_EMPTY

Durante una secuencia se iniciaron tres procesos.

Los dos primeros mostraron únicamente:

Godot Engine v4.7.1

y la información del renderer.

El tercer proceso ejecutó completamente
DeviceLifecycleTest.

Resultado:

DeviceLifecycleTest

Checks:
27

Failures:
0

Result:
PASS

Conclusión corregida:

La limpieza automática del panel Output contribuía
a ocultar resultados, pero no era la única causa.

Godot Editor puede iniciar un proceso de prueba
sin que la escena actual llegue a producir su salida.

La causa exacta dentro del mecanismo Run Current Scene
permanece sin determinar.

Estado de la investigación:

REABIERTA

Siguiente verificación:

Ejecutar la misma escena directamente desde
la línea de comandos en modo headless.

El resultado de línea de comandos será considerado
más confiable porque no depende del panel Output
ni del mecanismo Run Current Scene del editor.
