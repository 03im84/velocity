Decisiones aplicadas:

✔ DeviceCatalogDraft es editable.

✔ DeviceCatalog es inmutable.

✔ DeviceCatalog no tiene ID propio.

✔ DeviceCatalog no tiene versión propia.

✔ La identidad pertenece a DeviceProfile.

✔ Resolución utiliza Profile ID exacto.

✔ Resolución utiliza Profile Version exacta.

✔ Múltiples versiones pueden coexistir.

✔ Un mismo Profile ID puede tener
  versiones diferentes.

✔ Una identidad exacta duplicada
  es Structural Error.

✔ La misma instancia repetida
  también es duplicado.

✔ No existe overwrite.

✔ No existe last write wins.

✔ No existe first write wins silencioso.

✔ No existe get_latest().

✔ No existe fallback automático.

✔ No existe upgrade automático.

✔ No existe downgrade automático.

✔ Orden de entrada se conserva.

✔ get_profiles() devuelve copia.

✔ Draft posterior no modifica Catalog.

✔ Catalog permanece estable
  durante resolución.

✔ Catálogo vacío es válido.

✔ Profiles canónicos son aceptados.

✔ Profiles de usuario son aceptados.

✔ DeviceCatalog satisface
  DeviceProfileResolver.

✔ DeviceCatalog no depende
  de SystemProfileCompiler.

✔ SystemProfileCompiler no depende
  de la clase concreta DeviceCatalog.

✔ DeviceCatalog no contiene factories.

✔ DeviceCatalog no crea Devices.

✔ DeviceCatalog no construye Graph.

✔ DeviceCatalog no abre archivos.

✔ DeviceCatalog no conoce filesystem.

✔ Persistencia permanece externa.
