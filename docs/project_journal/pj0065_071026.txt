PJ0065 – Conditioned Distance Provider 1.0

Fecha: 07/10/2026

Baseline:

b688b8b feat(environment): add distance noise model

Milestone:

Playable Vehicle Composition 1.0
Stage 0 – Environment and Realism Foundations

Problema:

DistanceSensorRuntimeUnit consume providers mediante get_distance() e
is_valid(), pero Vehicle Composition necesita capturar un provider raw,
aplicar deterministic distance conditioning y madurar distance/validity
con latency acotada sin modificar el Slice existente.

Requisitos aprobados:

- preservar get_distance/is_valid;
- sample(timestamp) explícito para coordinator;
- source noise determinista y explícito;
- BoundedLatencyBuffer con capacity fija;
- timestamp monotónico;
- overflow observable;
- zero-noise/zero-delay preserva baseline;
- Last Known Good;
- sin DeviceBus, Measurement, RuntimeUnit o SceneTree ownership.

Alternativas:

1. Modificar PhysicsDistanceProvider.

Rechazada. Mezcla physics sampling con signal conditioning y rompe el
provider raw aceptado.

2. Modificar DistanceSensorRuntimeUnit.

Rechazada. Introduce environment concerns dentro de un Slice estable.

3. Adapter compatible compuesto externamente.

Seleccionada. ConditionedDistanceProvider implementa el contrato actual
y añade sample(timestamp) para VehiclePhysicsCoordinator.

Dependencias:

- raw Distance Provider Object;
- DistanceNoiseModel;
- optional NoiseSource Object;
- dedicated BoundedLatencyBuffer.

Semántica:

- is_configuration_valid valida dependencias;
- is_valid describe únicamente current matured reading;
- sample libera entries maduras antes de capturar;
- raw invalid no consume NoiseSource;
- valid raw usa un normalized sample cuando noise > 0;
- distance + validity viajan juntas por latency;
- sample devuelve false si enqueue es rechazado;
- zero-delay madura en la misma llamada;
- invalid matured reading conserva Last Known Good distance;
- clear vacía queue, reinicia epoch y elimina current reading;
- drain budget nunca excede max_entries.
