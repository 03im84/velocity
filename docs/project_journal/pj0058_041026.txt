PJ0058 – Hover Physics Slice 1.0 Problem and Analysis

Fecha: 04/10/2026

Baseline:

9b677c5 docs(propulsion): record propulsion runtime baseline

Target:

Playable Vertical Slice 1.0

Dependency:

Distance Sensor Runtime Slice 1.0

Problema:

Convertir DistanceMeasurement válido en una fuerza de lift estable, finita y acotada por hover point, sin acoplar todavía RuntimeUnit a RigidBody3D o a una topología completa de nave.

Física seleccionada:

height_error = target_height - distance

distance_rate = distance_delta / time_delta

raw_lift = equilibrium_force
+ stiffness * height_error
- damping * distance_rate

lift = clamp(raw_lift, 0, max_lift_force)

Equilibrium force:

Necesaria para sostener peso en target con rate cero. La distribución futura de peso se configura por point; no se calcula automáticamente en 1.0.

Alternativas:

A. RayCast + RigidBody monolítico.
Rechazada: mezcla sensor, policy, body y lifecycle.

B. Spring sin damping.
Rechazada: oscilación persistente.

C. Damping desde body velocity.
Diferida: requiere body/frame antes de Vehicle Composition.

D. Controller central multi-point.
Diferida: adelanta pitch/roll y topología completa.

E. Hover point independiente con derivative de distancia.
Seleccionada.

Decisión aprobada:

Aprobar Alternativa E.

Políticas temporales:

- first sample usa rate cero;
- timestamp debe avanzar;
- sample gap debe estar acotado;
- timing inválido no aplica fuerza y rebase temporal;
- measurement inválido no aplica fuerza y limpia history;
- sink failure conserva sample válido;
- siguiente sample puede recuperar.

Force policy:

- finite;
- lift-only;
- minimum 0;
- maximum explícito;
- no stale force;
- no unbounded history.

Multi-point futuro:

Cada sensor se conecta a un HoverPoint exacto mediante source filtering. Playable Vehicle Composition añadirá múltiples points, sinks físicos y balancing sin reescribir Point 1.0.

Stability acceptance:

Se exige simulación determinista 1D con masa, gravedad y fixed timestep para demostrar bounds, finitud, oscilación decreciente y convergencia antes de usar Godot Physics.
