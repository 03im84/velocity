Problema:

ProximityLiftModel calcula una fuerza distance-only, pero todavía no existe
Managed Runtime Unit que consuma DistanceMeasurement y entregue esa fuerza
a un actuator por point sin modificar HoverPoint 1.0.

Decisión:

Añadir `ProximityLiftPointRuntimeUnit` como actuator independiente con el
mismo lifecycle Managed Runtime de Propulsion/Hover y un sink específico.

Contrato:

profile_id: velocity.proximity_lift.point
profile_version: 1
activation_context: SIMULATION
capability: proximity_lift_force
input_port: in.distance_measurement
subscribes: distance_measurement
sink: apply_proximity_lift_force(force_newtons, timestamp) -> bool

Responsabilidades:

- validar Configuration exacta;
- preservar model y sink BORROWED;
- implementar CREATED/INITIALIZED/READY/RUNNING/SHUTDOWN;
- exponer únicamente endpoint distance_measurement;
- validar BusMessage, Topic, DistanceMeasurement y timestamps;
- calcular force mediante ProximityLiftModel;
- revalidar finitud y model bounds;
- exigir resultado booleano del sink;
- exponer last force y ValidationReport por intento.

No responsabilidades:

- distance derivative;
- spring/damper;
- sample history;
- source filtering;
- DeviceBus publishing;
- RigidBody3D;
- global balancing;
- HoverPoint modification.

Source filtering permanece en Managed Runtime binder. Un sensor puede
alimentar HoverPoint y ProximityLiftPoint mediante connections explícitas.
