Problema:

La Unit está aceptada, pero CompositionRuntime necesita construirla por el
mismo RuntimeFactory contract utilizado por Propulsion y Hover, sin crear
model/sink internamente ni introducir Host Objects.

Decisión:

Añadir `ProximityLiftPointRuntimeFactory` especializada y construct-only.

Contrato:

profile_id: velocity.proximity_lift.point
profile_version: 1
activation_context: SIMULATION
model dependency: proximity_lift_model
sink dependency: proximity_lift_force_sink

Ambas dependencias deben ser BORROWED.

Build:

- valida RuntimeConstructionRequest;
- valida exact RuntimeFactoryKey;
- valida exact DeviceConfiguration;
- exige ProximityLiftModel válido;
- exige sink con apply_proximity_lift_force;
- construye ProximityLiftPointRuntimeUnit;
- construye RuntimeDeviceHandle sin Host Objects;
- conserva bindings exactos;
- no ejecuta initialize/ready/start ni actuation.

Release:

- null/invalid/wrong-key Handle se rechaza;
- Primary debe ser ProximityLiftPointRuntimeUnit;
- Host Objects deben permanecer vacíos;
- Unit activa se rechaza;
- CREATED o SHUTDOWN se acepta;
- repeated release es idempotent;
- BORROWED model/sink permanecen vivos.
