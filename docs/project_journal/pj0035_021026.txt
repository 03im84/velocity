Hardware:

CompositionCompiler 1.0:

SIMULATION-ONLY

Hardware produce:

HARDWARE_SAFETY_ERROR

Razón:

DeviceGraphSnapshot.is_valid()
representa validez para Simulation.

Snapshot no conserva por sí mismo
el ValidationReport upstream.

Un ciclo puede ser:

SIMULATION_HAZARD

permitido en Simulation

bloqueante en Hardware

Compiler no puede reconstruir
con certeza toda evidencia upstream
desde Snapshot solamente.

No se permite compilar Hardware
sin un contrato sucesor que incluya
evidencia de seguridad explícita.

No se añade upstream report
como quinto argumento en 1.0.

Razón:

El report de CompositionCompiler
tiene scope de compilación.

El caller conserva reports upstream.

Una futura Composition Orchestrator
podrá agregar evidencia completa.

Ciclos:

Compiler no ejecuta topological sort.

Conserva orden del Snapshot.

CompositionPlan utiliza phase barriers.

Un ciclo válido para Simulation
no impide construir Plan.

Registry stability:

Compiler usa un Registry snapshot.

CompositionRuntime deberá recibir
la misma instancia.

Plan no contiene Registry.

Result no contiene Registry.

La preservación de referencia
pertenece a Composition Root futura.

No se inventa Registry ID
o content hash.

Error aggregation:

Device stage agrega errores
para todos los Nodes.

Connection stage agrega errores
para todas las Connections.

Existe gate entre stages.

No se generan errores derivados
de Connections cuando Device stage
ya es inválido.
