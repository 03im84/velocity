Problemas analizados:

✔ Existían dos declaraciones globales
  de DistanceProvider.

✔ DistanceProvider utilizaba RefCounted
  como clase base.

✔ PhysicsDistanceProvider necesitaba Node3D.

✔ ManualDistanceProvider dependía de
  variables no declaradas.

✔ Las pruebas físicas anteriores utilizaban
  DeviceBus como Node.

Decisiones:

✔ Provider será un rol arquitectónico.

✔ No existirá una clase base universal
  obligatoria.

✔ Distance Provider utilizará el contrato:

  - get_distance()
  - is_valid()

✔ ManualDistanceProvider heredará
  directamente de RefCounted.

✔ PhysicsDistanceProvider conservará Node3D.

✔ DistanceSensorDevice validará el contrato
  durante initialize_sensor().

✔ DeviceBus nulo será rechazado.

✔ Provider nulo será rechazado.

✔ Una inicialización fallida no creará
  estado parcial.

✔ Provider no conocerá DeviceBus.

✔ Provider no construirá BusMessage.

✔ Provider no construirá DistanceMeasurement.

✔ DistanceReading fue pospuesto.

✔ Las pruebas anteriores tendrán sucesoras.
