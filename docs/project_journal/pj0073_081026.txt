Problema:

SteeringCommand representa yaw intent, pero falta un model puro que combine
command torque con damping y yaw-rate limiting sin conocer RigidBody,
motion source o torque sink.

Decisión:

Añadir YawSteeringModel inmutable con torque escalar acotado.

Parámetros:

max_yaw_torque_newton_meters >= 0
yaw_damping_newton_meter_seconds >= 0
max_abs_yaw_rate_radians_per_second > 0

Formula:

command_torque = normalized_yaw * max_yaw_torque
damping_torque = -yaw_rate * yaw_damping
raw_torque = command_torque + damping_torque
output = clamp(raw_torque, -max_yaw_torque, max_yaw_torque)

Yaw-rate policy:

Si abs(yaw_rate) >= max_abs_yaw_rate y normalized_yaw intenta aumentar el
rate actual, command_torque se suprime. Damping permanece activo. Un command
opuesto al rate permanece activo para recuperar control.

Safety:

- invalid configuration fails neutral;
- normalized yaw fuera de [-1, 1] fails neutral;
- non-finite normalized yaw/rate fails neutral;
- non-finite raw torque fails neutral;
- output siempre queda dentro de torque limits.

No responsabilidades:

- YawMotionSource;
- SteeringTorqueSink;
- DeviceBus;
- SteeringCommand parsing;
- Vector3/RigidBody;
- mutable configuration.
