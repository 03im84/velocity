Problema resuelto:

DeviceGraphDraft hereda de RefCounted
y, por tanto, de Object.

Los nombres connect() y disconnect()
entraban en conflicto con los métodos
nativos de Object y producían un error
de firma durante el parsing.

Corrección:

✔ connect() fue reemplazado por connect_ports().

✔ disconnect() fue reemplazado por disconnect_ports().

✔ La API pública ya no oculta métodos
  nativos de Object.

✔ Engineering Standards registra la
  obligación de revisar métodos heredados
  antes de nombrar APIs públicas.

Implementación completada:

✔ DeviceGraphDraft permite añadir Devices.

✔ DeviceGraphDraft permite retirar Devices
  sin Connections activas.

✔ Connection IDs son deterministas.

✔ El formato de Connection ID es:

  source_device|source_port|target_device|target_port

✔ El separador `|` está reservado.

✔ Source Device y Target Device son validados.

✔ Source OutputPort y Target InputPort
  son validados.

✔ Source Topic y Target Topic deben coincidir.

✔ Semantic Kinds deben ser compatibles.

✔ UNSPECIFIED funciona como wildcard semántico.

✔ Self-connections son rechazadas.

✔ Connections duplicadas son rechazadas.

✔ Las operaciones fallidas preservan el Graph.

✔ disconnect_ports() es transaccional.

✔ Devices conectados no pueden eliminarse.

✔ get_connections() retorna una colección
  independiente.

✔ TopicChannels son reconstruidos después
  de operaciones válidas.
