Problema:

DeviceBus utilizaba publicación reentrante
síncrona depth-first sin límites.

Una topología cíclica podía producir:

- stack overflow;
- message storm;
- queue ilimitada;
- pérdida de control del proceso principal.

Decisiones:

✔ Dispatch FIFO iterativo.

✔ Reentrant publish se encola.

✔ El call stack no crece por reentrada.

✔ Dispatch Cycle explícito.

✔ Publication Budget.

✔ Callback Budget.

✔ Queue Size Limit.

✔ Dispatch Time Budget.

✔ Hard maximums obligatorios.

✔ Abort controlado.

✔ Recovery en un ciclo posterior.

✔ DeviceBusDispatchPolicy.

✔ DeviceBusDispatchReport.

✔ configure_dispatch_policy().

✔ get_dispatch_policy().

✔ get_last_dispatch_report().

✔ Policy bloqueada después del primer ciclo.

✔ DELIVER_ALL.

✔ Coalescing descartado.

✔ Single Semantic Owner.

✔ DeviceBus realiza fan-out.

✔ No republishing sin transformación.

✔ Derived Outputs utilizan contratos nuevos.

✔ Provenance permanece fuera de DeviceBus.

✔ Thread confinement.

✔ Time Budget separado de determinismo.

✔ Payload Size documentado como limitación.
