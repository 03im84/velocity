Lifecycle order:

Política seleccionada:

Phase barriers

+

Device Entry insertion order

Fases:

1. construction

2. attach

3. initialize

4. set_ready

5. start

Cada fase termina para todos
antes de comenzar la siguiente.

Orden de:

construction

attach

initialize

set_ready

start

se deriva directamente de:

CompositionDeviceEntries

Shutdown:

orden inverso de Device Entries

Rollback:

orden inverso de adquisición

No se almacenan Arrays
duplicados por cada fase.

Razón:

Evita siete secuencias
que puedan contradecirse.

Ciclos:

DeviceGraph permite ciclos.

No se utiliza topological sort
como requisito universal.

Phase barriers permiten:

- construir todos;

- adjuntar todos;

- inicializar todos;

- preparar todos;

antes de iniciar cualquiera.

Scheduling avanzado futuro podrá usar:

- SCC;

- grupos;

- temporal boundaries;

- prioridades;

sin cambiar la identidad básica
de Device Entries.

DeviceBusDispatchPolicy:

Es obligatoria dentro del Plan.

Razones:

- reproducibilidad;

- budgets explícitos;

- VP-002;

- no depender de defaults ocultos;

- misma política entre compile
  y runtime.
